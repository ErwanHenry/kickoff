## Résumé

**Bug :** l'inscription (POST `/api/auth/sign-up/email`) renvoyait un 500 sans corps en production.

**Cause racine réelle (≠ hypothèse $defaultFn) :** le schéma Drizzle des tables
better-auth ne correspondait pas au modèle exigé par better-auth v1.5.6 :

1. **`account` sans colonne `id`** — better-auth exige sa propre PK `id` ;
   `accountId` est l'identifiant côté provider (= userId pour les comptes
   credential), PAS la clé primaire. L'adapter Drizzle levait
   `BetterAuthError: The field "id" does not exist in the "account" Drizzle schema`
   → 500 sans message. (C'était l'erreur visible dans les logs Vercel du
   2026-04-01T17:00Z — la piste était la bonne, elle a été abandonnée à tort.)
2. **`session` sans `created_at`/`updated_at`** — better-auth les écrit à chaque
   création de session (autoSignIn) → aurait crashé juste après le fix du point 1.
3. **Table `verification` absente** — requise par le plugin magic link.

La piste `$defaultFn(() => nanoid())` était une fausse piste : better-auth
génère lui-même les IDs côté application, aucun défaut (SQL ou Drizzle) n'est
nécessaire sur les tables auth.

**Preuve :** test d'intégration `src/lib/__tests__/integration/auth-signup.test.ts`
(better-auth réel + adapter Drizzle réel + schéma réel sur PGlite in-memory).
Avant le fix il reproduisait l'erreur prod à l'identique ; après le fix :
signup → user + account + session créés, doublon → 422 USER_ALREADY_EXISTS,
signin OK, magic link → ligne en table verification. Suite complète : 84/84.
